# 2.2.0 播放旋转与断点续播修复

2026-11-18，在已同步上游 `5f60e371` 的 fork `486f960` 上核对并修复用户反馈的两项问题。版本仍为 2.2.0，修复包用 `playback-fix` 后缀与上一轮安装包区分，不创建发布标签。

## 发现与修复

上游 2.2.0 调整了横屏手势坐标、全屏控件和画面比例，但未覆盖本次两个场景。新增回归经过用户明确同意，先在未修改的生产代码上运行，两项均失败：

- 旋转：播放收藏 A（991）后，旧滚动延迟回调切到了 B（992），断言 `992 !== 991`。
- 续播：收藏中已有第 2 集进度，实际媒体请求却为第 1 集，断言 `1 !== 2`。

修复后：

- 系统旋转、容器宽高变化只重新对齐当前内容，不根据过渡期高度选择另一部视频；取消旧滚动候选，提交前复核尺寸和位置。移除条目切换后 120/350ms 的旧位置回拉，避免干扰快速往返。
- 观看进度集中到 `src/features/feed/useWatchProgress.ts`：进入视频默认读取当前片库的集数与秒数；用户显式选集从该集开头播放。切换视频/集数、失活和卸载时补存最新实际观察值，不再仅靠每 5 秒的节流写入。
- 取得播放地址不提前写入默认进度；恢复前零时间事件不会冲掉已保存位置。账号和清空历史代次保护保留，旧播放器清理不能恢复已清空的历史。
- 没有改动收藏、存储迁移格式、网络兼容或 401 规则；Feed 提取进度关注点后，尺寸预算由 1489 下调到 1429。

## 验证结果

- `pnpm build`、文档链接、尺寸预算、`git diff --check` 通过。
- `rotation`：模拟 WebKit 先报告缩短高度的 scroll、随后报告旋转的顺序；保持 A、同一个 video 元素和播放秒数，转回竖屏仍为 A。
- `resume`：真实 Profile 收藏入口恢复第 2 集；手动选集从头播放；在五秒写入周期内跳到 37 秒后立即 A→B→A，仍恢复第 2 集约 37 秒；退出收藏再进入、刷新后保持进度；清空历史后的旧播放器卸载不会回填。
- 既有 `seek/legacy/lifecycle/gesture/proxy/portrait-fit/ios-native/recovery` 全部通过（其中 iOS 媒体契约 36 项）。合并执行时 resume 曾因测试选错“切集开关”定位失败；改为真实“视频详情 → 选集”入口后，resume 单独复测通过，没有削弱断言。
- `test-storage-migration`、`test-session-expiry`（22 项）、`test-api-loading` 通过。Rust 未修改，本轮不重复运行已在同步阶段通过的 Rust 全套测试。
- 测试使用本地 HLS 和模拟 IPC；真实 iPhone 系统旋转和 AVFoundation 仍需真机验证。
