合并前 fork：`7fd91d10a3e64606e5b292797dbdcd59f8be4be2`（1.3.0）。

## 合并取舍

- 界面、播放器、业务 API、动态选线、自定义镜像、应用代理及发布流程使用上游 2.0.0 实现。
- 保留 fork 的 NAT64 兼容：对 `64:ff9b::/96` 解出 IPv4 再执行原有安全规则，公共地址可用，私网和回环仍拒绝。上游的系统代理识别、代理路由和 IPv6 优先逻辑同时保留。
- 保留并更新 AGENTS.md；原 1.3.0 指南完整归档到 `docs/build-history/2026-11-14-v1.3.0.md`。
- 补充下面的版本间迁移；未修改应用 Bundle ID，继续使用 `com.hghubx.app`。

## 收藏与观看记录

首次升级读取 fork 的 `app_data_v1:default:library` 与上游的 `hghubx_app_v1`，兼容更早的 `hghub_app_v1`：

- 收藏、点赞、关注和搜索记录合并去重；上游新键存在时，不用更早 HGhub 的旧键覆盖它。
- 同一视频选取 `at` 较新的观看记录，保留集数、播放秒数与总时长；同一时间优先 fork。仅有数字 ID 的旧记录不会覆盖带进度的较新记录。
- 音量、启动静音、切集和高清偏好优先使用 fork 保存的值。
- 写入新数据前，将原始值存入 `hghubx_library_backup_v2`；原 library 键也保留。备份或目标写入失败时不覆盖原值，后续启动重试。
- 迁移标记和新数据一次写入；后续取消收藏、清空观看记录、重启应用，不会重新导入已删除的记录。

## 接入地址

使用上游动态选线。原 `source.json` 在 `line.json` 不存在时导入；迁移要求地址符合上游的 HTTPS 根地址规则，原文件保留。已有 `line.json` 始终优先。

自动选线受已保存的开关控制；手动保存镜像会关闭自动选线，可在“设置 → 网络”重新开启。更换 origin 后可能需要重新登录，迁移不会把其他 origin 的账号凭据转交给新站点。

## 安装与数据范围

- macOS：退出正在运行的 HGhubX，再用 DMG 中的同名 App 覆盖；不要先清理应用数据。
- iOS：在原设备上覆盖安装同 Bundle ID、同开发团队签名的包；不要先卸载应用。
- 旧 `HGhub.app` / `com.hghub.huangguo` 属于另一应用容器，此次不会自动复制其存储或凭据。
- macOS 使用 ad-hoc 签名，未进行 Apple 公证；iOS 使用本地开发签名，安装范围取决于描述文件。
