# HGhubX 2.1.1：登录失效提示与数据保留

基于 fork 的 2.1.0（上游基线 `1620817`），未额外同步上游提交。

## 问题与行为

旧凭据被服务器拒绝时，2.1.0 仍显示缓存的用户资料，收藏、点赞及历史同步只报告 `401`。本次增加明确的“登录已失效，请重新登录”提示和入口，个人页注明正在显示本机缓存。

- 失效后保留当前账号的收藏、点赞和观看记录，游客片库独立保留；不自动退出账号、不删除存储、不把账号记录复制到游客片库。
- 暂停自动同步和上传，继续记录本机观看进度。成功重新登录后恢复同步；失败的收藏、点赞写操作不会自动重放。
- 请求发起时捕获账号代次；迟到的 401 不影响后来登录的账号、重新登录后的同一账号或新线路。失效后的迟到成功写响应也不能覆盖保留的缓存。
- HTTP 403 作为权限拒绝处理；普通网络故障、登录表单验证失败及游客请求不会误标当前账号失效。
- 多个并发 401 共用一处失效播报；重新登录按钮支持键盘和触控，登录表单打开时隐藏背景提示，取消后仍可浏览缓存。

## 验证与发布

新增 `pnpm test:session-expiry`，使用本地模拟 IPC 验证桌面/移动提示、登录错误、取消/重新登录、账号/线路切换、迟到响应、失效期间保存与重启后的进度，以及成功重新登录后恢复上传。
另运行已有迁移、账号同步、清空历史、对话框、前端构建和 Rust 检查。模拟测试不等于真实站点的会话过期测试；不修改用户凭据来制造 401。

版本同步为 2.1.1，Android versionCode 为 2001001，Bundle ID 仍为 `com.hghubx.app`。Universal DMG 与开发签名 IPA 沿用已有本地构建流程；覆盖安装前备份实际片库，安装和启动后比较收藏与观看进度。构建产物、私有快照和验证日志只保存在忽略目录，不提交设备或签名身份。

本次提交前验证：登录失效回归全部通过；原有迁移、账号同步空状态、清空历史确认、对话框及前端构建通过。Rust 全目标检查通过，103 项单元测试通过，4 项联网测试忽略。
